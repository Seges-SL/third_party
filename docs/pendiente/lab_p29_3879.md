```bash
e3sql <<'SQL'
SELECT id, canvas_rev,
       position('</script><script>alert' IN canvas_design) > 0 AS cierra_script,
       position('<!--<script>' IN canvas_design) > 0 AS comentario,
       position(chr(92) || 'u003c/script' || chr(92) || 'u003e' || chr(92) || 'u003cscript' || chr(92) || 'u003ealert' IN canvas_design) > 0 AS escapado,

```

  para el código de este commit; si cambia ese CSS, hay que cambiar la marca.

**Avisos para 6b y 6d:**

- Con peticiones cortas («pon el fondo azul») el orquestador puede reinterpretarlas como una página nueva

Para 6b, 6c y 6d, `ai_log` de Design y del rechazo. Las llamadas a Design dejan su fila de dos formas: en el
turno del chat, `result_summary` empieza por `Design` y la página que devolvió está en `result_data`; en el
camino del fulfill (botón de lienzo o job), `user_prompt` empieza por `Lay out the tables of one chat answer as
a page.` y la respuesta está en `result_summary` (recortada a 5000 caracteres). La columna `crudo` dice si la
respuesta de Design lleva el valor hostil sin escapar.

La consulta está pensada para lanzarla justo después de cada prueba (últimos 15 minutos); para revisar
después, cambiar `now() - interval '15 minutes'` por `'<reinicio>'` (la hora del apartado 4).

```bash
e3sql <<'SQL'
SELECT id, create_date,
       left(regexp_replace(coalesce(user_prompt, ''), '[[:space:]]+', ' ', 'g'), 50) AS peticion,
       left(regexp_replace(coalesce(result_summary, ''), '[[:space:]]+', ' ', 'g'), 140) AS resumen,
       position('</script><script>alert' IN coalesce(result_data, '') || coalesce(result_summary, '')) > 0 AS crudo
  FROM ai_log
 WHERE create_date > now() - interval '15 minutes'
   AND ((result_summary ILIKE 'Design %')
        OR (result_summary ILIKE 'No page was built%')
        OR (user_prompt ILIKE '%Lay out the tables of one chat answer as a page%'))
 ORDER BY id;
SQL
```

Textos esperados en `result_summary`:

- página o edición guardada: `Design changed the page in N s (M chars)` (o `Design laid out the page…`
  si Design rehízo el documento; `Design failed after…` si falló);
- caso 2 de B1 rechazado: la fila de Design y después
  `No page was built: the change left a value of the page as markup`;
- caso 3 de B1 rechazado: solo `No page was built: the open page has no figures to keep; change it with its rows`
  (no se llama a Design).

`crudo = t` en una fila de Design y la página guardada con `cierra_script = f` (página de rescate o rechazo):
Design copió el valor y el parche 29 lo frenó.

El caso 3 de B1 (página sin tabla ni `DATA`) no se puede provocar desde el chat: lo cubren los tests
(`test_edit_page_without_data`).
