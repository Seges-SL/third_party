**Consulta C** (se usa en varios apartados; cambia `E3P_SESSION` delante para mirar otra sesión):

```bash
e3sql <<'SQL'
SELECT id, canvas_rev,
       position('</script><script>alert' IN canvas_design) > 0 AS cierra_script,
       position('<!--<script>' IN canvas_design) > 0 AS comentario,
       position(chr(92) || 'u003c/script' || chr(92) || 'u003e' || chr(92) || 'u003cscript' || chr(92) || 'u003ealert' IN canvas_design) > 0 AS escapado,
       position(chr(92) || 'u003c!--' || chr(92) || 'u003cscript' || chr(92) || 'u003e' IN canvas_design) > 0 AS comentario_escapado,
       position('pns-page-rows-visible' IN canvas_design) > 0 AS rescate,
       position('th{background:#eef1f7}' IN canvas_design) > 0 AS pagina_rescate
  FROM chatboo_session WHERE id = :sesion;
SQL
```

- `rescate`: la tabla del servidor está visible (`<style id="pns-page-rows-visible">`, de `_force_rows_visible`).
  Sale en la página de rescate del parche 29 y también cuando el servidor conserva el diseño y solo hace visible su
  tabla (rescate del fabricante, `chatboo_canvas.py:2384` y `:2389`). La sesión 11 ya lo da.
- `pagina_rescate`: la página es la de rescate (`_page_for_rows`), la que usa el parche 29 cuando descarta el diseño.
  La marca es un fragmento del CSS de `_page_for_rows` (`th{background:#eef1f7}`, `chatboo_canvas.py:1177`): vale
  para el código de este commit; si cambia ese CSS, hay que cambiar la marca.

Para saber el id de la sesión de un chat recién hecho:

```bash
e3sql <<< "SELECT id, canvas_rev, write_date FROM chatboo_session WHERE user_id = 2 ORDER BY write_date DESC LIMIT 3;"
```

Para 6b y 6d, `ai_log` del rechazo o de la página:

```bash
e3sql <<'SQL'
SELECT id, create_date, left(regexp_replace(coalesce(result_summary, ''), '\s+', ' ', 'g'), 140) AS resumen
  FROM ai_log WHERE create_date > now() - interval '15 minutes'
   AND (result_summary ILIKE 'Design %' OR result_summary ILIKE 'No page was built%')
 ORDER BY id;
SQL
```

Textos esperados en `result_summary`:

- página o edición guardada: `Design changed the page in N s (M chars)` (o `Design laid out the page…`
  si Design rehízo el documento; `Design failed after…` si falló);
- caso 2 de B1 rechazado: la fila de Design y después
  `No page was built: the change left a value of the page as markup`;
- caso 3 de B1 rechazado: solo `No page was built: the open page has no figures to keep; change it with its rows`
  (no se llama a Design).

El caso 3 de B1 (página sin tabla ni `DATA`) no se puede provocar desde el chat: lo cubren los tests
(`test_edit_page_without_data`).
